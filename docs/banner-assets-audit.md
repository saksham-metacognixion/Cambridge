# Banner assets audit: client delivery of 16 Oct 2026 ("Cambridge Hospital - Website Images")

Audit date: 19 Oct 2026. Audit only: no client file and no site file was changed. Client folder: `~/Downloads/Cambridge Hospital - Website Images` (two sub-folders, `Banners - UAE` and `Banners - KSA`; the OneDrive zip `~/Downloads/OneDrive_2026-10-16-2.zip` holds the same 118 files, CRC-verified).

**Baseline and its limits.** The site builds every hero from a transparent people cut-out (`src/assets/**/<key>-cutout.*`, drawn at the live-site size recorded in `src/data/banner-art.json`) over a CSS gradient and the shared outline pill stack (`src/assets/banners/pills.svg`). Most of those cut-outs were extracted from the client's earlier 16 Oct composites (`docs/client-assets/website-images-oct16`, gitignored). **That earlier folder is not on this machine**, so the comparison baseline is the cut-out actually in use on the site, decoded losslessly (AVIF/WebP via the project's `sharp`), not the client's previous originals. Scale-aware pixel comparison and sharpness were measured with Pillow; every pair was also checked by eye on contact sheets (`sheets/*.png` in the session scratchpad).

> **Erratum (19 Oct 2026, implementation pass).** The "x1.37 larger composition" finding below is wrong. It came from reading the 2880 px frame as 2x of the 1440 stage; the project maps the client frame to the banner as 500/1370 live px per composite px (`tools/banners/composite.py` NEW_SCALE, right-aligned to the stage), exactly as for the 16 Oct files. Measured during implementation, the people in these files sit at the same scale and spot as the cut-outs now in use (alignment scale 0.73 cut-out px per composite px for every 2x asset, i.e. identical geometry; the outline pill stack is the same 1540 composite px = 562 live px). So: no composition change, no copy-column overlap, no scale decision needed; the files are drop-in sharper sources for the existing `banner-art.json` geometry. The per-file "People drawn x1.37 larger" notes and the overlap table in section E should be read as "same size as today" (the CSV responsive column was corrected). Everything else in the audit stands.

## A. Executive summary

- Image files discovered: **118** (all PNG, all readable, 0 corrupted). 116 are 2880x1370 RGBA composites with no transparency; 2 are the 1107x1421 Careers intro photo (not a banner).
- Unique files by content: **83**; **35** files are byte-for-byte duplicates of another file (33 duplicate groups, mostly the same file placed in both the UAE and the KSA folder).
- Valid banner candidates (2880x1370 files that map to a site banner): **114** (81 unique pictures). Plus 2 files for a page that does not exist ("Knowledge Centre").
- Existing banners matched: **114** file-to-asset pairs.
- Quality classification: **Improved 100**, **Unchanged 6**, **Worse 5**, **New asset 7**, **Unable to compare 0** (per file; duplicates are counted per file).
- Missing required banners: **2** genuinely missing (Your Opinion Matters for Global and UAE); **54** Global pages have no Global file at all (the delivery has no "Banners - Global" folder) and can only be served by the UAE file if the client confirms that Global uses the UAE pictures; 20 condition-page banners and 4 calculator banners are not part of this delivery (existing assets stay).
- Invalid files: **0**. Files needing manual review / client answers: **13** (see sections C, D and F).

**Headline findings**

1. **Same pictures, bigger composition.** 100+ of the files are the photos already on the site. They are composed about **x1.37 larger** than the live geometry (people and pill stack alike: the outline pill stack measures ~750-800 live px wide in these files vs 562 px on the site). The 2880x1370 frame is the Figma 1052x500 banner at 2.74x, with the people at Figma size rather than the live-site size that the 14 Oct brief fixed. Used as composed, the people would start 550-800 live px from the left at 1440 and overlap the desktop copy column on most pages (section E). Used only as a sharper source for the existing cut-out geometry, they are a clear win.
2. **Real resolution gain on the banners that were still 1x.** Every KSA care banner and ~12 Global care banners are served today from 579x450 (1x) cut-outs with visibly low detail; the new files carry 2-4x their measured sharpness at the same output size. Banners that were already cut at 2x from the 16 Oct composites (About, Careers, Why, Who We Are, Find a Doctor, Patient Hub, hospitals, ...) gain a little (x1.1-1.8) or nothing.
3. **Regional variants dropped (regression).** 33 duplicate pairs put the same file in both folders. For four pages the KSA folder now holds the UAE picture although the site has a distinct KSA picture today: **KSA Who We Are, KSA Inpatient Care, KSA Long-Term Care & Rehabilitation hub, KSA Your Opinion Matters** (which also lost the Bug 195 request for a whole head). The UAE Long-Term Acute Care file is the KSA pairing. This conflicts with the project rule "never mix images across regions" and needs the client's confirmation.
4. **Previously reported edge defects.** The new files are solid (no ghosted beds, chairs or clothing; the bottom rows carry no black line). Two files still cut furniture flat on the side that faces the copy: **Insurance Providers** (new photo, desk and chair cut) and **Speech & Language Therapy** (desk, as before); the Musculoskeletal parallel bars end flat as before. Nothing in this delivery fixes the Bug 195/197 condition-page edges (no condition files).
5. **Genuinely new pictures:** Conditions & Specialities (replaces the low-res "heart in hand"), Insurance Providers, KSA Physical Medicine (red shemagh variant), KSA Patient Testimonials (new mother), UAE Home (first client file for it), and an unassigned "Knowledge Centre" banner.
