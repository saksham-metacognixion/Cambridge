## Bug 188 — hero pill stack cut at the screen edge — Completed

**Root cause.** The shared outline pill stack (562 live px wide, placed per banner from the client composite) is wider than
most people boxes and overhangs them on the end side. `BannerArt` positioned the *people box* on the 72 px content edge
(phones/tablets: the padding edge), so the overhang ran off screen; `bleed: "end"` banners pushed the whole art out by a further
10 px.

**Fix (fb4eb3a).** `BannerArt.astro` computes the stack's end overhang `--oe` (= `ove * w`, live px) and
- desktop (≥1024): `inset-inline-end: calc((72 + var(--oe)) * var(--lp))` — the content edge now holds the stack, or the people
  where the stack is inside them;
- tablet (690-1023): `margin-inline-end: calc(var(--oe) * var(--s) * var(--lp))` on non-bleed frames;
- phones: the art sizes to fit the stack inside the padding;
- `bleed: "end"` frames: only the *people* are translated out by `--oe` + 10 px; the stack stays on screen.
Five compositions (Find a Doctor, Homecare Global, FAQ, Media Hub, Feedback …) were also re-placed from the client files
(`pill_place.py` writes w/h + pills). No pill was shrunk.

**Verification (this session, staged merge).** Every page with a `.bn-frame` in the build: **496 pages** (Global / UAE / KSA,
English + Arabic = 248 RTL pages, 46 `bleed: end` pages) × **14 widths** (320, 360, 375, 390, 414, 430, 440, 768, 820, 1024,
1280, 1440, 1920, 2560) in **Chrome** (6944 checks) and **WebKit** (Safari engine, 6944 checks) — measured: pill-stack
and people rects vs the viewport *and* vs the nearest `overflow: hidden/clip` ancestor, `document.scrollWidth`.

## Bug 190 — image sharpness — Completed

**Root cause.** No `quality` was set anywhere, so Astro's sharp service encoded every AVIF at sharp's default **q50 (4:2:0)** and
WebP at q80: soft faces, smeared beards and fabric.

**Fix (fb4eb3a).** `src/lib/image-service.ts` wraps Astro's sharp service and writes a default `quality` into each transform
(**AVIF 80, WebP 85, JPEG 85**; PNG untouched) — in the transform, so it is part of the cache key / file name and a cached q50
file can never be served again; `astro.config.mjs` adds AVIF chroma 4:4:4. Applies to every `<Picture>`/`<Image>` site-wide
(the client's complaint covers non-banner photos too); a per-image `quality` prop still wins. Widths / `srcset` / `sizes` /
`loading` / `fetchpriority` / `width` + `height` unchanged; nothing upscaled (`withoutEnlargement`).

**Verification (this session).** For every banner `<picture>` in the 496 pages, the largest desktop candidate per source and
format (**229 served variants**, 124 AVIF + 105 WebP) was re-encoded from the source the way Astro does:
- **228 / 229 byte-identical** to the q80 (AVIF, 4:4:4) / q85 (WebP) encode, **0 / 229** identical to the old defaults (the one
  outlier, `feedback-hero-cutout … 270w`, differs by 0.1 KB and is +3 dB over the old encode) — the built files really carry
  the new settings; no stale cache.
- Detail kept (PSNR vs the Lanczos-resized source, over the banner grey): AVIF median **39.2 → 45.1 dB**, WebP **40.3 → 41.7 dB**.
- Bytes: sampled AVIF 2.75 → 6.09 MB (2.2×), WebP 4.43 → 5.08 MB (1.15×). Per page a desktop loads one variant: 1x AVIF
  median **13.8 → 30.1 KB**, largest 1x 52.9 KB; e.g. KSA Why 527w 15.2 KB → 33.5 KB, Accreditations 649w 28.5 KB, Home 674w
  59.3 KB (2x variants 68-126 KB). Sources: 1000-1160 px cut-outs (378-865 KB), i.e. ≥ 1.5× the largest rendered 1x width.
- Visual: `out/b190-crops.png` — 260 px native crops of source / old q50 / served for Accreditations, Physiotherapy,
  Long-Term Care, Home, Our Care, Cerebral Palsy, Testimonials, Al Ain, Refer a Patient, KSA Why: the served crops keep the
  beard, eye and fabric detail of the source; the q50 crops are visibly waxy (Physiotherapy, Refer, Home baby).
- Performance: the 9 Oct Lighthouse run (96-100 mobile on staging) predates this change; the extra ~17 KB per desktop hero and
  ~5 KB per phone hero (300w AVIF 13-19 KB) is within the budget, but **re-run Lighthouse on staging after deploy** to confirm 95+.
