# Bugs 256-260: unsaved-changes warning, empty Arabic tab, logo / favicon, author = reviewer, PR defaults (dashboard)

Date: 2 Nov 2026. QA baseline `2ae8e5d`. Built on the uncommitted bug 254-255 work. Nothing committed or deployed.
Dashboard = `tools/admin/`.

## Bug 256: leaving with unsaved changes

**Cause.** The editors already tracked unsaved changes (`unsaved.ts`, bug 255), but only "Publish site" read the flag.
`nav()` in `app.tsx` pushed the new address unconditionally, the browser's Back / Forward set the page straight from
`popstate`, and there was no `beforeunload` listener.

**Fix.**
- `unsaved.ts`: `confirmLeave()` opens the dialog "You have unsaved changes. Leave without saving?" (Stay / Leave, Esc = Stay)
  and resolves true when the page may be left. Only one dialog at a time: a second request gets the same answer. A
  `beforeunload` listener is added when the first editor becomes dirty and removed when none is (saved, discarded, unmounted).
- `app.tsx`: `nav(path, { force? })` asks first. `force` is used after a create, a rename and a delete, where the change is
  saved or the record is gone. Every dashboard history entry carries its position (`idx`). A Back / Forward with unsaved
  changes is undone at once (the address stays on the editor), the dialog asks, and Leave redoes the move. Sign out asks too.
  The dialog is a native `<dialog>` (`LeaveDialog`) styled with the dashboard's tokens (`.confirm` in `app.css`).
- Post editor, author editor, Settings: the flag is set in a layout effect, so it changes in the same commit as the screen.
  With a normal effect, a reload within one frame of "All changes saved." still got the old warning (seen in the browser run).
- Post editor: changing the web address is refused while there are unsaved changes ("Save your changes before changing the
  web address."). The editor reloads from the saved file after a rename, so the edits would be lost.

## Bug 257: empty Arabic tab blocked the English save

**Cause.** "+ Add Arabic" wrote `ar: { title: "" }` into the post. The save step removes empty fields, so the request carried
`ar: {}` and the schema answered `ar.title: Invalid input: expected string, received undefined`. The error list printed the
schema's field path and message as they are.

**Fix (`posts.tsx`).**
- Opening the tab only switches the view. The Arabic version is created by the first Arabic field filled in (`arStart`).
- On save, an Arabic version with nothing a person wrote in it is left out (`hasContent`: text fields, article text or
  media, takeaways, FAQs, sources). One with content but no title stops the save with "Arabic title is required. Add a title
  or remove the Arabic version." and nothing is sent; the Arabic text stays in the form.
- Server field errors are shown in words (`readable`), for example "Arabic title is required…", "English FAQ answer is
  required.", "\"Shown on\" needs at least one choice.". The server's own messages are already sentences and are shown as they are.
- "Remove Arabic version" is unchanged. Opening the Arabic tab no longer marks the post as changed.

## Bug 258: logo and favicon missing

**Cause.** `index.html` and `app.tsx` load `/admin/logo.svg` and `/admin/favicon.svg`. The server read them from the content
checkout (`CONTENT_ROOT`: `src/assets/header/logo.svg`, `public/favicon.svg`). They were not in `tools/admin/ui/`, and the
bundle did not copy them, so any install whose content root lacks those site files answered 404. The ticket names
`src/assets/logo.svg`, which does not exist. The site's header logo is `src/assets/header/logo.svg`.

**Fix.** `tools/admin/ui/logo.svg` is a copy of `src/assets/header/logo.svg` (the site header logo). `tools/admin/ui/favicon.svg`
is a copy of `public/favicon.svg` (the site's own Cambridge mark favicon). `bundle.mjs` copies both into `dist-admin/ui/`
next to `index.html` and `app.css`. `server.ts` serves them from the bundle through its existing `/admin/<file>` route; the
special case that read them from the checkout is removed. Both files are new and must be added to Git with the rest.

## Bug 259: the same person as author and reviewer

**Cause.** Nothing compared the two fields. The GEO check passed for any reviewer.

**Fix.**
- `server.ts` `validate()`: a post whose `reviewer` equals its `author` is refused with `400`, field `reviewer`, "The reviewer
  must be a different person from the author.". This covers create, save, restore and rename, through the API as well as
  the dashboard.
- `checks.ts`: "Reviewed by a clinician" passes only for a reviewer who is not the author. When they are the same, the tip says so.
- `posts.tsx`: "Reviewed by" lists everyone except the author. Choosing the current reviewer as author clears the reviewer
  and a toast says why. The save also checks it before sending.
- No existing post has the same author and reviewer, so no saved post is affected.

## Bug 260: "Consult for a Care Plan" on press releases

**Cause.** A new post had no hero settings. The checkbox reads "shown unless `hero_button` is false", so every type started
with the button. Changing the type only changed `type`.

**Fix (`posts.tsx`).**
- Defaults per type (`HERO`): Blog = button shown, strip hero. PR / News = button hidden (`hero_button: false`) and the whole
  photo in the hero (`hero_photo: "full"`). The only two press releases that set either (Oracle, Les Roches)
  have exactly these settings in both languages. The other 102 press releases have neither and are unchanged.
- Switching Blog to PR / News or back moves each setting to the new type's default unless it was changed by hand. That is
  either in this editor, or before: a value that is not the old type's default was chosen by someone. Both languages follow.
- A new Arabic version starts with the English version's button setting.
- The site already hides the button when `hero_button` is false (`media-hub/[slug].astro`). In the current build (2 Nov,
  10:17) the Oracle press release has no "Consult for a Care Plan" button on `/media-hub`, `/ae`, `/ar` and `/sa/ar`, and a
  blog post has it.
